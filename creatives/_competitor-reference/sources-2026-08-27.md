To re-fetch any of them at 640x640 (the ceiling without a logged-in session):

    curl -s -A 'facebookexternalhit/1.1' "https://www.instagram.com/p/<CODE>/" \
      | tr '>' '\n' | grep 'og:image"' | head -1 | sed 's/.*content="//;s/".*//;s/&amp;/\&/g'

A normal browser user-agent gets a JS shell with no OG tags — the crawler UA is what makes this work.
Full resolution (up to ~1440px) is only reachable through `/api/v1/feed/user/<id>/` with a logged-in
session; `/api/v1/users/web_profile_info/` 400s for business accounts, so resolve ids via
`/web/search/topsearch/?context=blended&query=<handle>`.

## Incident, recorded so it is not repeated

On 27 Aug 2026 all 23 screenshots from this session were copied into a staging folder and then
renamed in a loop whose timestamp extraction returned an empty string for every file. Each `mv`
therefore targeted the same filename and overwrote the last, leaving one file. The Desktop originals
had already been deleted with `rm`, which bypasses the Trash, and no APFS snapshot covered the
window. Eighteen screenshots were lost.

Two rules follow: never delete a source before the copy is verified *in its final name and location*,
and never batch-rename with a derived name without asserting the derived value is non-empty and
unique first.
